# iPad 适配与人工验收

本次实现 iPad 窗口自适应，维持 Expo SDK 57、现有 Bundle ID、EAS 配置和本地数据格式。代码检查不能替代原生编译与真机验收。目前状态：**代码已实现，双列面板优化后的真机复验和 TestFlight 待完成**。README 在验收前继续标注已发布版本支持 iPhone。

## 布局规则

使用当前窗口宽度减左右安全区计算可用宽度，不缓存屏幕尺寸，不使用横竖屏或设备型号决定单双列。

| 可用宽度 | 模式 | 内容宽度与间距 |
| --- | --- | --- |
| < 600 点 | 紧凑 | 普通 iPhone 保留原样；iPad 边距 16 点 |
| 600–1039 点 | 舒展单列 | 居中，最大宽度 720 点，边距 32 点 |
| >= 1040 点 | 双列 | 居中，最大宽度 1200 点，边距 32 点，列间距 24 点 |

最大宽度包含左右内容边距。今日与记录页双列保持左四右六，扣除 24 点列间距后按比例分配；不固定左列宽度。

今日页左侧直接显示绿色投入卡和添加入口，不显示“今日概览”或整列外框。右侧也不显示“任务列表”标题，仅将“正在进行”“接下来/待开始”“已完成”及各组任务分别放入白色分组卡片（16 点内边距、20 点圆角、细边框、组间距 16 点）。分组标题无额外顶部外边距，首组顶部与左侧绿色投入卡对齐；空状态放在右侧。继续使用整页滚动。

记录页左侧保留白色外框，内部是“日期列表”标题与简洁日期项，选中日期浅绿强调。右侧保留一张白色详情卡，标题直接显示“今日”或选中日期，不再出现“当日记录”，也不重复显示日期标题。两侧外框、内边距及标题起点保持一致，内容独立滚动、标题固定。

统计图表和分类明细继续等宽排列，仅跟随新断点和最大宽度。设置始终最大宽度 720 点单列。单双列断点与普通 iPhone 的原有显示路径保持不变。

iPad 时长编辑使用应用内底部数字面板，仅提供 0–9、退格和清空。该编辑器不挂载原生 `TextInput`，不请求系统键盘，因此不在系统浮动数字面板与完整键盘之间切换。分钟显示区点击后全选，第一次数字按键替换原值，后续追加；退格删除一位，全选时退格清空，清空后保存不可用，输入 0 可以保存。保存仍只接受非负整数，取消不写入草稿。

数字面板固定在当前 iPad 窗口底部并避开安全区；较矮窗口的编辑卡片可滚动。支持横竖屏和窗口缩放，旋转期间保留分钟草稿。仅改变 iPad 的时长编辑，其他文字编辑仍使用系统键盘，普通 iPhone 仍使用原数字键盘和透明弹窗。自定义面板使用屏幕按键输入，不依赖外接键盘。

其他 iPad 弹窗最大宽度 560 点，距离安全区至少 16 点；键盘出现时缩小可用空间，长内容可滚动。分类管理和语言选择保留内部滚动。底部导航高度为 56 点加底部安全区。iPad 支持四个方向，普通 iPhone 沿用原竖屏声明。

## iPhone 改动边界

- 紧凑普通 iPhone 不启用新的限宽、安全区、键盘或弹窗容器样式。
- `TaskCard`、`SwipeDelete`、全局设计常量、TimerContext、存储、计时和通知服务未修改。
- 每次只渲染一个页面布局，状态与操作回调留在页面层；尺寸变化不清空输入或编辑对象。
- iPad 休息状态只渲染一层遮罩，手机原休息界面保留。
- 不升级依赖、不切换构建镜像、不修改 Firebase 配置。
- 本次不含跨设备同步、新增任务排序或 Duo 完整支持。Android 和 Web 沿用原布局。

## Windows / EAS 真机开发

先在改动前的手机版本中记录四个页面、主要弹窗和休息状态，使用同一台 iPhone、相同语言与测试数据作对照。当前仓库已实现适配，未记录改动前的真机截图；可对照现有已安装版本。

如设备尚未注册，先运行以下命令并按提示在 iPad / iPhone 完成注册：

```powershell
eas device:create
eas build --platform ios --profile development
```

在两台设备上安装构建页面提供的开发包，按提示开启开发者模式。安装后，电脑与设备连接同一网络：

```powershell
npx expo start --dev-client --port 8085
```

在开发版打开项目链接。后续纯布局代码可通过 Metro 刷新；`supportsTablet`、方向声明等原生配置变化必须重新构建。已有 Apple Developer 签名、Expo 登录与相应构建环境是 EAS 真机包的前提。

不要通过 Web 改变窗口大小代替 iPad 原生验收：本次 Web 保持原布局，且不能验证原生弹窗、键盘、后台计时和通知。

## 双列面板优化复验

通过现有开发版的 Metro 刷新即可验证，无需重新 EAS 构建。iPad 可用宽度低于 1040 点时变成单列属于预期，包括部分 iPad 的竖屏；宽度达到断点后两页使用相同的列宽比例。今日按任务分组包框，记录页左右均保留白色外框，左侧日期项保持简单。

- 今日：无任务、仅待办、多个运行中、已完成较多时，左侧添加入口始终可用；绿色卡与右侧首个分组顶部对齐，无“今日概览/任务列表”外层标题。
- 记录：日期较多和当日任务较多时，两边各自滚动且标题固定；右侧以实际日期作标题、左侧只显示“日期列表”；日期选择、时长编辑和删除正常。
- 短窗口：缩放后面板不被固定最小高度撑出屏幕，内容仍能滚动到达。
- 在 1040 点附近切换单双列，输入值、编辑对象、选中日期保持。
- 快速检查普通 iPhone、单列、统计页及法语/俄语等较长标题。

## 自动检查与正式包

不增加布局快照或 E2E 框架。执行 `npm run typecheck`、`npm test`，并检查 Expo introspection 中设备族为 `[1, 2]`、iPhone 方向声明不变、iPad 四方向声明存在。现有页面交互测试仅补充新布局 Hook 的手机模式 mock，断言保持原样。

当前双列优化的本地验证：类型检查、现有测试、全部 13 种语言的键与面板文案检查通过。此前 iPad 基础适配的原生配置 introspection 和 iOS Metro / Hermes 导出也已通过（`.expo/ipad-validation`），该导出不是签名 IPA。本轮未重新打包；简化后的视觉效果与设备操作仍需开发版人工复验，TestFlight 验收待完成。

人工确认开发包后，再生成 production 构建并通过 TestFlight 验收：

```powershell
eas build --platform ios --profile production
eas submit --platform ios --profile production --latest
```

确认提交的构建号，待 App Store Connect 处理完成并配置测试资格后，在两台设备安装 TestFlight 包，复验启动、计时、后台、通知及弹窗。补齐 iPad 商店截图并完成验收记录后，再更新 README 的发布支持范围和提交正式发布。
